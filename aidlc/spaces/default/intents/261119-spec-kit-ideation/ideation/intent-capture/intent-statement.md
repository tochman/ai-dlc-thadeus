# Intent Statement: EPIC-14 Spec Kit

## Problem Statement

Developers whose projects follow Spec Kit cannot use THADEUS at all, because the app accepts a project only when it has AI-DLC's `aidlc/spaces/` folder. [Q1]

This work checks the EPIC-14 stories (US-1401 to US-1407) as unvalidated raw input: their underlying problem, their feasibility against the current codebase and stack, missing requirements and conflicts, and an MVP and out-of-scope split. It stops at the Ideation to Inception gate. [desc]

## Target Customer

- The person running this workflow, on their own projects. [Q2]
- Other THADEUS users who already run Spec Kit projects. [Q2]
- Teams choosing between AI-DLC and Spec Kit. [Q2]

They benefit by working on a Spec Kit project in the same app they use for AI-DLC projects. [Q1] [Q2]

## Success Metrics

- The first version works when a person can set up a new project on Spec Kit from the app and start its first feature there. [Q3]
- Measured as pass or fail on one new project: Spec Kit set up from the app, and a first feature started from the app. [Q3]

## Initiative Trigger

Someone the person works with asked for Spec Kit support, for a project of theirs. [Q4] [Q8]

What they need first is to set up a new project on Spec Kit from the app (US-1405, US-1406). [Q9]

## Initial Scope Signal

- Workflow-selected scope: `bugfix`, workflow-selected, run as an Ideation-only plan. [scope]
- User-confirmed product boundary: nothing in US-1401 to US-1407 is excluded from the first version up front. [Q7]
- Setting up Spec Kit in a project (US-1405) is raised from Medium to High priority: setup is part of the first version. [Q10]

None.
