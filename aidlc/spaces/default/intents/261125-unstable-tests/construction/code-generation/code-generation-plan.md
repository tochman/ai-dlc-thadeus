# Code Generation Plan: two unstable tests (US-0052)

## Summary

- Builds: two tests that no longer depend on timing: the agents working now, and opening the token detail
- Touches: `tests/renderer/ConfigView.test.jsx` and `tests/renderer/TokenDetail.test.jsx` only
- Tests: no new ones; the two are made to fail on the fault first, then fixed, and run 50 times

## Causes

- **ConfigView:** the row is in the DOM before React has run the effect that starts the view's interval (`ConfigView.jsx`, `WorkingAgents`), so the clock can move before there is a timer. The view is right; the test must wait for the timer.
- **TokenDetail:** the test looks up headings by role in the whole document, which is slow in jsdom, and is also the file's first test, so it carries the first render's cost. To be measured in Step 2. No limit is raised.

## Steps

- [x] **Step 1** Run the two files as `unit-test-instructions.md` says, to see the runner green.
- [x] **Step 2** Measure where the token detail test spends its time, and show that the ConfigView test fails when the timer is not started before the clock moves.
- [x] **Step 3** ConfigView: wait until the view's timer is started before the clock moves. It still fails when the counter does not update (checked by stopping the interval in the view for one run, then put back).
- [x] **Step 4** TokenDetail: make the measured slow part cheap. It still fails when focus does not come back (checked the same way).
- [x] **Step 5** Both pass 50 times in a row, and under load; ESLint and Prettier clean.

Story to step: US-0052, Steps 2–5.
