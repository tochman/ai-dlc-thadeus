# Code Generation Plan: US-0024 The "Tokens over time" chart is drawn

## Summary

- Builds: gives the chart's size box a height, so the "Tokens over time" chart is no longer clipped to nothing
- Touches: `src/renderer/TokenDetail.jsx`, new `tests/renderer/TokenDetailChartSize.test.jsx`
- Tests: 2 renderer tests (1 regression with the real `ParentSize`, 1 for the one-reading sentence)

## Root cause

visx 4's `ParentSize` puts its children in an absolutely positioned box with `overflow: hidden` inside an outer box styled `height: 100%`. In the token detail section (a flex column with no set height), that outer box ends up 0 px tall, so the box with the chart in it is 0 px tall too. The SVG is drawn but clipped away, and the legend below it still shows. The existing renderer tests mock `ParentSize` (`tests/renderer/TokenDetail.test.jsx:11`), so they never saw it.

## Requirements (from `docs/features/epic-00-fixes.md` US-0024)

- **FR1**: with two or more readings and Diagram selected, the chart is drawn (one series per token kind, figures on hover or focus).
- **FR2**: with fewer readings than a chart needs, the view says so in one sentence.
- **FR3**: a test fails without the fix and passes with it; the full suite stays green.

## Steps

- [x] Step 1: Verify the runner: `npx vitest run tests/renderer/TokenDetailChartSize.test.jsx` (renderer project, jsdom). (FR3)
- [x] Step 2: Frontend Red: new test file without the `@visx/responsive` mock. With two readings, the size box (`.token-detail-size`) must have the chart's height (260 px). Record the failing output; today its height is `100%`. (FR1, FR3)
- [x] Step 3: Frontend Red/guard: with one reading, Diagram shows the one sentence `tokenDetail.empty.oneReading` and no size box. (FR2; already true, so this guards it rather than going red)
- [x] Step 4: Frontend Green: in `TokenDetail.jsx` pass `parentSizeStyles={{ width: '100%', height: CHART_H }}` to `ParentSize`. Add a comment naming US-0024 FR1. (FR1)
- [x] Step 5: Refactor with the suite green: `npx vitest run tests/renderer/` and Prettier on the changed files. (FR3)
- [x] Step 6: Documentation and traceability: `code-summary.md`, `traceability.json`. (FR1–FR3)

Not applicable: data model, data access, business logic, API, build configuration (none change).
