# Requirements Analysis Questions: US-0604, filter epics and user stories

Today each epic's page has two filters of its own (status and priority), which are forgotten when you leave the page. The story adds release, epic, complexity and free text, combined, with a count and a clear-all action, remembered per project. These questions settle how it looks and what is kept.

## Question 1
Where should the filters sit?

A. One filter bar at the top of the Epics tab. When any filter is set, the view shows one list of the matching stories from every epic (each row names its epic), with the count; cleared, it shows the epic list as today. The per-epic filters go away.
B. Keep filtering per epic page and add the new filters there; the epic filter then narrows the epic list on the left instead
X. Other (please specify)

[Answer]: X. Both: the filter bar on the Epics tab, and the filters on each epic's page

## Question 2
What should be remembered per project?

A. Every filter, the free text included
B. Every filter except the free text, which starts empty each time
X. Other (please specify)

[Answer]: X. None: no filter is remembered
