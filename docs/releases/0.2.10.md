# Release plan v0.2.10

> Release plans list the stories a release takes from several epics. The epics stay organised by topic; status lives in [FEATURES.md](../FEATURES.md) and in each epic file.
>
> Previous release: v0.2.9 (less waste: lower token cost per intent, and no lost planning work).

**Theme:** Clearer views of past and present work: token history for finished intents, honest agent progress, planning changes that are never lost, readable intent names, a calm pipeline view, release plans that stay true when a story moves, a dialog that opens on the page that just arrived, and a start screen that says what is missing and what is not signed in.

**Baseline (2026-11-18):** An audit of US-0215 found that only its first criterion already holds: the token view draws every stored reading, and the 120-reading window applies only to the live wave (`src/renderer/tokenFlow.js`). Rebuilding from transcripts, the "no history on this machine" sentence and the figures strip are not built. AI-DLC 2.11.3 has no `intent rename` (only `switch`, `archive`, `unarchive`), so US-0508 keeps a display name beside the slug. US-0804 (sign-in state) is not built; it joins the release and is built before US-0805, so the health check ships with sign-in state.

**Working rules for the release:**
- One story at a time, each on its own branch (`fix/US-0028`, `fix/US-0029`, `feat/US-0215`, `fix/US-0030`, `feat/US-0608`, `feat/US-0609`, `feat/US-0508`, `feat/US-0804`, `feat/US-0805`, `fix/US-0031`). If two run side by side, merge `main` into the later branch and run the whole suite again before its Build and Test is approved (project rule).
- TDD: a failing test first. During the loop run only the test being worked on; the full suite runs once before Build and Test is approved, and in CI.
- A fresh session after each stage.
- Each story's marker goes 🚧 at start and ✅ when approved, in its epic, the epic's Status line and FEATURES.md.
